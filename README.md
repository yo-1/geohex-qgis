# geohex-qgis

ポリゴンレイヤ（日本の陸域など）またはラインレイヤ（路網など）と重なる **GeoHex v3** の六角形セルを生成する QGIS プラグインです。
QGIS の Processing アルゴリズムとして実装しているため、ツールボックス・バッチ処理・モデラー・Python コンソールから同じ形で使えます。

> **検証状況（0.1.0）**
> - GeoHex コア（`geohex_v3.py`）: 公式 v3.2 JS ソースからの移植。他実装の公開サンプル出力（Ruby・Perl・TypeScript・PL/pgSQL・ES2015・Python の README、計7例）と一致することを確認済み。**公式 JS (`hex_v3.2_core.js`) をNode.jsで直接実行し、920件（固定代表点×複数Level、日本域・世界域の乱数点、日付変更線・極付近を含む）を全件突き合わせ、不一致0件を確認済み**（`tests/test_geohex_v3.py` の `OfficialJSCrossValidationTest` に代表的な値を回帰テストとして格納）。
> - セル列挙（`cell_selector.py`）: 総当たり判定との一致を単体テストで確認済み。
> - QGIS 連携部分（`algorithm.py` ほか）: **QGIS 実機では未実行**（QGIS API の簡易スタブでの動作確認のみ）。実機テストが最初の作業です。

## GeoHex の性質（要点）

| 項目 | 内容 |
|---|---|
| 格子 | Web メルカトル平面（`H_BASE = 20037508.34` m）上の正六角形。上下の辺が水平（flat-top） |
| レベル | 0〜15。コード長は `レベル + 2` 文字（例: レベル6 → `XM488548`） |
| セルの大きさ | `h_size = H_BASE / 3^(レベル+3)`。外接円半径 = 辺の長さ = `2 * h_size`。レベルが1つ上がると長さ 1/3、面積 1/9 |
| 面積の均等性 | **均等ではない**。地上の長さは `cos(緯度)` 倍、面積は約 `cos²(緯度)` 倍。日本（北緯24〜46°）では南北で面積が約1.7倍違う |
| 階層 | コードの桁が3進の位置情報に対応する近似的な階層。子セルは親セルの境界をまたぐため、**厳密な入れ子ではない**。コードの前方一致でまとめると、親の六角形ではなく「中心＋隣接6＋左右2」の9セルの塊になる |
| セル判定 | 点 → セルの対応は決定的で、入力データに依存しない（コードをキーに結合・集計できる） |
| 表示 | EPSG:3857 で見ると正六角形。EPSG:4326 では縦に潰れて見える |
| 注意 | 版により互換性なし（v1/v2/v3）。**レベルの番号や大きさの対応も版・実装で異なる**ため、他の資料の数値は流用しない。本プラグインは v3.2（レベル 0〜15）。日付変更線・極付近には特別処理があるが、日本域では影響しない |

**用途の向き不向き**: 人が読める短いコードでの索引・可視化には向きます。面積補正なしの密度比較や、統計データ（国勢調査など）との突き合わせには **JIS 標準地域メッシュ**、面積の均一性が必要なら H3 なども検討してください。

性質・利点と欠点・ユースケース・既存メッシュとの置き換え評価は **[docs/GEOHEX_GUIDE.md](docs/GEOHEX_GUIDE.md)** にまとめています（根拠の強さを付記。効果が未検証の提案を含みます）。

### レベルの目安（日本の陸域）

`面積` は北緯36°での1セルの地上面積。`セル数` は陸地面積 約37.8万 km² ÷ 1セル面積の**粗い概算**で、海岸線の被覆セルを含む実際の出力数とは一致しません。

| レベル | 頂点間の幅（メルカトル上） | 面積（北緯36°） | セル数（概算） |
|---:|---:|---:|---:|
| 4 | 36.6 km | 571 km² | 約 660 |
| 5 | 12.2 km | 63.4 km² | 約 6,000 |
| 6 | 4.07 km | 7.05 km² | 約 5.4万 |
| 7 | 1.36 km | 0.78 km² | 約 48万 |
| 8 | 0.45 km | 0.087 km² | 約 430万 |
| 9 | 0.15 km | 0.0097 km² | 約 3,900万 |

レベル8以上を日本全域で生成するのは、Python 実装では現実的ではありません（都道府県・市区町村単位に絞ってください）。

## 機能

- 入力: ポリゴンまたはラインレイヤ（任意の CRS。内部で EPSG:4326 に変換）。「選択地物のみ」も利用可
- **陸域かどうかの判定は行わない**。入力ジオメトリがそのまま対象範囲になる（海を含むポリゴンなら海のセルも出る）
- 抽出条件（ポリゴン入力）: 「陸域と少しでも重なるセル（被覆）」または「セル中心が陸域内にあるセル」。ライン入力は常に「線が通るセル」
- 出力: EPSG:4326 のポリゴン。属性 `code`, `level`, `x`, `y`, `lon`, `lat`（中心）, `area_m2`（WGS84楕円体上の面積[m²]。6頂点ポリゴンを `QgsDistanceArea` で測定。フィールド計算機の `$area` と同じ方法）
- 複数パート・複数地物にまたがる重複セルは1件だけ出力
- 出力セル数の上限（既定 200万）を超えると中断（暴走防止）

## 対象環境

- QGIS 3.40 以降を想定（`metadata.txt`）。**QGIS 4.x（Qt6）は未検証**のため `qgisMaximumVersion` は未設定
- Python: QGIS 同梱のものを使用。追加パッケージ不要
- 開発・テスト: Python 3.12、標準ライブラリの `unittest` のみ

## インストール（開発中）

1. QGIS で「設定 → ユーザープロファイル → アクティブなプロファイルフォルダを開く」（英語UI: *Open Active Profile Folder*）
2. `python/plugins/` に `geohex_generator` フォルダをそのままコピー
3. QGIS を再起動し、「プラグイン → インストールと管理」で **GeoHex Generator** を有効化
   （実験的プラグインとして扱われるため、設定で「実験的プラグインも表示」が必要な場合があります）

元に戻すには、プラグインを無効化して `python/plugins/geohex_generator` を削除します。

## 使い方

### GUI

プロセシングツールボックス → **GeoHex → GeoHexグリッドを作成（ポリゴン範囲）**

1. 対象範囲ポリゴンレイヤ（陸域）を選ぶ
2. レベルを指定（日本全域なら 6〜7）
3. 実行し、出力を EPSG:3857 のプロジェクトで表示すると六角形が正しく見える

### Python コンソール（QGIS）

```python
import processing

processing.runAndLoadResults(
    "geohex:generate_geohex_grid",
    {
        "INPUT": "C:/data/japan_land.gpkg|layername=land",  # 実際のパスに置き換える
        "LEVEL": 6,
        "MODE": 0,  # 0: 重なるセル / 1: 中心が陸域内
        "MAX_CELLS": 2000000,
        "OUTPUT": "TEMPORARY_OUTPUT",
    },
)
```

### 路網（ライン）に対して生成する

ラインレイヤ（例: 道路ネットワーク）を入力にすると、線が通るセルだけを出力します。
面積のない線には「中心が陸域内」を適用できないため、抽出条件は常に「重なるセル」です。

- 目安（粗い上限）: セル数 ≒ 対象地域の面積 ÷ 1セル面積。路網が地域全体を覆わなければ、これより少なくなります。
  神奈川県（約2,400 km²）なら、レベル7で約3,000、レベル8で約2.8万、レベル9で約25万が上限の目安です。
- 入力の地物数が多い（数十万本以上）場合の所要時間は未計測です。まず地域を絞ってレベル7で試してください。

### 陸域データについて

本プラグインはデータを同梱しません。国土数値情報の行政区域データ、国土地理院の基盤地図情報などを別途取得してください。
**利用条件の確認は利用者側で行ってください。** 湖沼や海面を含むかはデータにより異なるため、「陸上」の定義に合うかも確認が必要です。

## テスト

QGIS 不要の部分（`geohex_v3`, `cell_selector`）は次で実行できます。

```powershell
# PowerShell 7 / リポジトリのルートで実行
python -m unittest discover -s tests -t . -v
```

QGIS 連携部分は自動テスト未整備です。実機での確認項目:

- 小さなポリゴン（数市町村）でレベル 5〜7 を実行し、出力が期待どおりか
- 「選択地物のみ」、CRS が JGD2011（EPSG:6668）/ 平面直角座標系の入力
- ライン入力（路網）で、線が通るセルだけが出力されること。「中心が陸域内」を選んだときに警告が出ること
- 無効ジオメトリを含むデータ、離島の多いデータ
- 実行中のキャンセル、出力先を GeoPackage にした場合
- `area_m2` が、フィールド計算機の `$area`（プロジェクト楕円体を WGS84 に設定）と一致すること。北ほど小さくなること（同一レベルで北海道と沖縄を比較）
- プラグインの無効化→再有効化を繰り返してもツールボックスに重複登録されないこと

## 設計上の要点

- **セル列挙**: 入力ポリゴンの各パートの bbox をブロックに分割し、(1) 陸域と無関係なブロックはスキップ、(2) 全セル中心が陸域内なら全セル採用、(3) それ以外は GEOS の prepared geometry でセルごとに判定。日本のように bbox の大半が海の形状でも、bbox 全体を走査しない。
- **セル形状**: 公式 `getHexCoords` と同じ6頂点を EPSG:4326 に出力。辺は経緯度上の直線。メルカトル上の直線との差は、セルサイズに比べごく小さい（レベル7で数mm程度の概算）。
- **面積**: 出力CRS(度単位)では測れないため、`QgsDistanceArea` で WGS84 楕円体上の面積を求める。メルカトル平面上の面積（`6√3·h²`）は地上面積ではないため属性にしていない。
- **座標軸順序**: 経度・緯度の順（x=経度）。JGD2011 と WGS84 の差は本用途のセルサイズに比べ十分小さい。
- **バックグラウンド処理**: Processing 標準の実行機構に任せ、`processAlgorithm` 内で GUI・プロジェクトに触れない。

## トラブルシューティング

| 症状 | 確認 |
|---|---|
| ツールボックスに GeoHex が出ない | プラグインが有効か。QGIS の「Python エラー」ログ（ログメッセージパネル）を確認 |
| 「出力セル数が上限を超えました」 | レベルを下げる／対象を絞る／上限値を引き上げる |
| 生成が遅い | レベルを1下げるとセル数は約 1/9 になる。入力の頂点数が極端に多い場合は簡略化も検討 |
| 出力が縦に潰れて見える | プロジェクト CRS を EPSG:3857 にする（EPSG:4326 表示では仕様上そう見える） |
| 出力が0件 | 実行ログの「入力: フィーチャ N 件 → 対象パート …」を確認。「選択地物のみ」で選択が0件、ポイントなど対象外の入力、座標変換の失敗がないか |
| 島が抜ける | 抽出条件を「陸域と少しでも重なるセル」にする（「中心が陸域内」は小さな島が抜ける） |
